# Geometry — ESP / Engineering Sketch Pad

## Files

- `tsangpo.csm` — top-level parametric model. 30P30N 3-element wing
  (slat + main + outboard flap, all built by `udpFitcurve`) plus a
  Hershey-bar NACA 0010 H-tail. No fuselage, no V-tail, no prop solids.
- `airfoils/30P30N_{Slat,Main,Flap}.dat3` — McDonnell-Douglas 30P30N
  validation coordinates, normalized to unit chord, padded to the
  3-column (x, y, z=0) format `udpFitcurve` expects.
- `render.py` — STL → 2x2 PNG with top / full-side / zoomed-airfoil views.
- `out/<case_name>/` — per-case STL bodies + `airframe.step` + an
  `airfoils` symlink (generated by `flow360/build_geometry.py`).
- `out/tsangpo_geometry.png` — the rendered 2x2 figure.

## What the CSM builds

Bodies (each emitted as its own STL so the renderer can color them):

| body         | shape       | section          | thickness / extent          |
|--------------|-------------|------------------|-----------------------------|
| `slat_right` | Hershey bar | 30P30N slat      | ~0.45 ft, full semi-span    |
| `slat_left`  | Hershey bar | 30P30N slat      | mirror of `slat_right`      |
| `main_right` | Hershey bar | 30P30N main      | ~0.43 ft, full semi-span    |
| `main_left`  | Hershey bar | 30P30N main      | mirror of `main_right`      |
| `htail_right`| Hershey bar | NACA 0010        | 10 % chord (≈0.28 ft in Z)   |
| `htail_left` | Hershey bar | NACA 0010        | mirror of `htail_right`     |
| `flap_right` | Hershey bar | 30P30N flap      | ~0.63 ft, spans `[flap_y_in, flap_y_out]` |
| `flap_left`  | Hershey bar | 30P30N flap      | mirror of `flap_right`      |

Slat and flap deflections are **baked into the 30P30N coordinates** (the
"30P30N" label literally means 30° slat / 30° flap). There is no
runtime flap-rotation step.

The propellers are **not** built here; Flow360 models them directly as
actuator disks (see `flow360/run_matrix.py`).

## Design parameters driving Study 1

| CSM despmtr        | Default | Sweep values (per `params.study1_matrix`) | Meaning                                                                  |
|--------------------|---------|-------------------------------------------|--------------------------------------------------------------------------|
| `gap_fraction`     | 0.00    | {0.00, 0.35}                              | inboard fraction of semi-span with the **flap** suppressed (slat continuous) |
| `Z_tail_chords`    | 0.00    | {0.00, 2.50}                              | H-tail vertical position, in chords above the wing plane                |
| `X_tail_mac`       | 3.50    | fixed                                     | H-tail longitudinal arm, in chords aft of wing c/4                      |
| `flap_outboard_eta`| 0.95    | fixed                                     | outboard end of the flap on the semi-span                               |
| `ncp_fit`          | 25      | fixed                                     | B-spline control points per 30P30N element (fit smoothness)             |
| `slat_LE_idx`      | 144     | fixed                                     | row index of the slat LE inside `30P30N_Slat.dat3` (split point)        |
| `main_LE_idx`      | 123     | fixed                                     | row index of the main LE inside `30P30N_Main.dat3`                      |
| `flap_LE_idx`      |  98     | fixed                                     | row index of the flap LE inside `30P30N_Flap.dat3`                      |
| `tail_naca`        | 0010    | fixed                                     | H-tail airfoil (symmetric)                                              |

`flow360/build_geometry.py` writes a tiny `despmtrs` file per case and
invokes `serveCSM -batch tsangpo.csm -despmtrs <file>`, producing
`out/<case>/{wing,htail,flap}_{left,right}.stl` and `airframe.step`.

## Numbering & conventions

- Origin at wing root quarter-chord on the symmetry plane.
- +X aft, +Y starboard, +Z up.
- Prop index runs 1 (inboard) → 5 (outboard) per semi-span; positions
  live in `params.PROP_Y_NONDIM`. Prop *geometry* is not in the CSM.

## ESP / OpenCSM gotchas baked into the CSM

These look benign but cost hours if you guess them; they are explicitly
commented in `tsangpo.csm`.

- **`udprim naca` returns a sketch in the XY plane**, with thickness in
  Y. Every NACA in the file is followed by `rotatex 90 0 0` to swing the
  thickness into Z (matching the convention `fighter3.csm` uses). The
  same swing is applied to the `udpFitcurve` sheets that build the
  30P30N elements.
- **`udpFitcurve` needs a `split`** for closed contours, otherwise it
  errors with `egads_degen: wraparound geometry with only one Edge`.
  We split each 30P30N element at its leading-edge (min-x) point; the
  indices are `despmtr`s in the CSM.
- **`udpFitcurve` filename arg** is a CSM string, prefixed with `$`:
  `udprim fitcurve filename $airfoils/30P30N_Main.dat3 ncp ncp_fit`.
  Relative paths resolve against `serveCSM`'s cwd, which is why
  `flow360/build_geometry.py` drops a symlink `case_dir/airfoils ->
  geometry/airfoils` before invoking serveCSM.
- **`rotatey angDeg zaxis xaxis`** — the pivot args are (z, x), not
  (x, z), per `OpenCSM.c`. (No longer used in this CSM because the
  flap deflection is baked into the 30P30N coordinates, but the rule
  still applies if you reintroduce a rigid rotation.)
- **`udprim naca Series NNNN`** is the only legal NACA invocation; the
  alternative camber/thickness keyword pair is not accepted in our ESP
  build.
- **No `END` inside a `MARK` block.** The block is closed by the
  subsequent `RULE` / `BLEND` / `LOFT`; a stray `END` is interpreted as
  "end of file" and silently truncates the model.
- **Bodies are disjoint solids on purpose.** We do not boolean-union the
  slat, main, flap, and H-tail; the 30P30N elements have *physical* slot
  gaps between them, and Flow360 expects them as separate boundaries
  anyway.
- **`udpFitcurve` is iterative.** With `ncp_fit` ≥ 50 the fit can take
  minutes per element; 25 is the smallest value that still resolves the
  30P30N upper and lower surfaces well. Bump it only if your post needs
  finer surface curvature.

## Rendering

```bash
source ~/esp/ESP129/EngSketchPad/ESPenv.sh
python flow360/build_geometry.py          # writes geometry/out/<case>/...
env -u PYTHONPATH python3 geometry/render.py  # writes geometry/out/tsangpo_geometry.png
```

`env -u PYTHONPATH` is required because `ESPenv.sh` exports ESP's Python
3.12 site-packages on `PYTHONPATH`, which collides with the system Python
3.10 numpy/scipy/trimesh.
