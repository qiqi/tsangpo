# Geometry — ESP / Engineering Sketch Pad

## Files

- `airfoils/estol_config.yaml` — single source of truth for the
  3-element airfoil stack and its Fowler kinematics.
- `airfoils/build_estol_geometry.py` — reads the YAML, builds each
  element as a smooth-spline closed contour, simulates the rigid
  Fowler kinematics for stowed / takeoff / landing, and writes:
  - `airfoils/{main_wing,vane,flap,tail}.udc` — OpenCSM UDC sketches
    (consumed by `tsangpo.csm` via `udprim $/airfoils/<name>`).
  - `airfoils/{main_wing.dat, vane_stowed.dat, flap_stowed.dat, tail.dat}`
    — Selig coordinate files for plotting.
  - `airfoils/estol_configurations.png` — 3-panel kinematics
    validation figure (stowed / takeoff / landing).
- `tsangpo.csm` — top-level parametric ESP model. Phase-parameterized
  (`despmtr phase 0/1/2`), full-span main wing, rigid vane+flap
  assembly with optional inboard gap, single-piece inverted-LS(1)-0417
  H-tail. No fuselage, no V-tail, no prop solids (Flow360 carries the
  props as actuator disks).
- `render.py` — STL → 2 × 3 PNG (top + side-section, one column per
  phase) using SI units throughout.
- `out/<phase>/` — per-phase STL + per-body STEP (`main_wing`, `vane`,
  `aft_flap`, `htail`, or their `_{right,left}` variants when
  `gap_fraction > 0`). Generated by direct `serveCSM` invocation, see
  *Build* below.

## What the CSM builds

Each lifting element is built from a closed planar UDC sketch in the
XY plane, swung into the XZ plane by `rotatex 90`, scaled to chord,
translated to its root Y-station, and extruded along +Y.

| body              | shape       | section                  | kinematics                                       |
|-------------------|-------------|--------------------------|--------------------------------------------------|
| `main_wing`       | Hershey bar | LS(1)-0417, coved        | full span, fixed                                 |
| `vane` / `vane_{right,left}`         | Hershey bar | NACA 9621                | rigid Fowler (rotatez + translate) before scale |
| `aft_flap` / `aft_flap_{right,left}` | Hershey bar | NACA 6311                | rigid Fowler (same kinematics as vane)          |
| `htail`           | Hershey bar | inverted LS(1)-0417      | fixed at `Z_tail_chords · MAC`                  |

When `gap_fraction == 0` the vane + aft-flap pair is a single
full-span body each; when `gap_fraction > 0` each becomes left/right
panels spanning `[gap_fraction · wing_semispan, flap_outboard_eta ·
wing_semispan]`.

The Fowler kinematics live as despmtrs driven by the `phase` selector:

| phase | name    | dx (·c) | dy (·c) | rotation (deg) |
|------:|---------|--------:|--------:|---------------:|
| 0     | stowed  | 0.000   | 0.000   |   0.0          |
| 1     | takeoff | 0.290   | 0.040   | −40.0          |
| 2     | landing | 0.320   | 0.055   | −65.0          |

These match `kinematics.phases` in `estol_config.yaml`.

## Design parameters

| CSM despmtr        | Default | Sweep values                              | Meaning                                                              |
|--------------------|---------|-------------------------------------------|----------------------------------------------------------------------|
| `phase`            | 0       | {0, 1, 2}                                 | Fowler stage: stowed / takeoff / landing                             |
| `gap_fraction`     | 0.0     | {0.0, 0.35} for Study 1                   | inboard fraction of semi-span with the vane+flap suppressed          |
| `flap_outboard_eta`| 0.95    | fixed                                     | outboard end of the vane+flap on the semi-span                       |
| `pivot_x` / `pivot_y` | 0.550 / −0.048 | fixed                              | Fowler pivot in stowed-chord-normalized coordinates                  |
| `Z_tail_chords`    | 0.0     | {0.0, 2.5} for Study 1                    | H-tail vertical position, in chords above the wing plane             |
| `X_tail_mac`       | 3.5     | fixed                                     | H-tail longitudinal arm, in chords aft of wing c/4                   |
| `wing_area_m2`     | 15.33   | fixed                                     | wing reference area                                                  |
| `wing_AR`          | 8.0     | fixed                                     | wing aspect ratio                                                    |
| `htail_span_frac`  | 0.35    | fixed                                     | H-tail span as a fraction of wing span                               |
| `htail_AR`         | 4.5     | fixed                                     | H-tail aspect ratio                                                  |

## Face naming — `capsGroup`

Every face is tagged with `attribute capsGroup $<name>` right after
its `extrude` so Flow360's geometry processor can group faces by tag
(`geo.group_faces_by_tag("capsGroup")` in the submit scripts).
**Do not rely on body dump order or `body0000N` renaming** — that
breaks every surface lookup the moment you reorder dumps in the CSM.

## Build

Driven by direct `serveCSM` invocation, one phase at a time:

```bash
source ~/esp/ESP129/EngSketchPad/ESPenv.sh

# Refresh UDCs / .dat files / validation PNG from the YAML
python geometry/airfoils/build_estol_geometry.py

mkdir -p geometry/out/{stowed,takeoff,landing}
for phase_id in 0 1 2; do
    name=$(printf "stowed\ntakeoff\nlanding\n" | sed -n "$((phase_id+1))p")
    echo "phase $phase_id" > geometry/out/$name/phase.despmtrs
    ln -snf $PWD/geometry/airfoils geometry/out/$name/airfoils
    (cd geometry/out/$name && \
     serveCSM ../../tsangpo.csm -batch \
              -despmtrs phase.despmtrs -outLevel 0)
done

env -u PYTHONPATH python3 geometry/render.py   # writes geometry/out/tsangpo_geometry.png
```

`env -u PYTHONPATH` is required because `ESPenv.sh` exports ESP's
Python 3.12 site-packages on `PYTHONPATH`, which collides with the
system Python 3.10 numpy/scipy/trimesh.

For Flow360 submission the CSM is inlined (UDC bodies pasted in
place of each `udprim $/airfoils/<name>`) and uploaded as a single
`.csm` file — see `inline_udcs()` in `flow360/submit_cruise.py`.
Multi-file STEP uploads only surface-mesh `body00001` (Flow360
limitation as of 25.9.x; see `flow360/LESSONS.md`).

## Conventions

- All dimensions in **metres**, angles in **degrees**.
- Origin at wing root quarter-chord (of the stowed 3-element chord)
  on the symmetry plane.
- +X aft, +Y starboard, +Z up.
- Prop index runs 1 (inboard) → 5 (outboard) per semi-span; positions
  live in `params.PROP_Y_NONDIM`. Prop **geometry** is not in the CSM.

## ESP / OpenCSM gotchas baked into the CSM

These look benign but cost hours if you guess them; they're explicitly
commented in `tsangpo.csm`.

- **MARK / RULE.** Closed by the subsequent `RULE` / `BLEND` / `LOFT`;
  a stray `END` inside a `MARK` block is interpreted as end-of-file
  and silently truncates the model.
- **`rotatey angDeg zaxis xaxis`** — the pivot args are (z, x), not
  (x, z), per `OpenCSM.c`. We don't currently `rotatey` anything, but
  the rule still bites if you reintroduce a rigid rotation.
- **`udprim naca Series NNNN`** is the only legal NACA invocation;
  the alternative camber/thickness keyword pair is not accepted in
  our ESP build. (The vane and aft flap don't use the `naca` UDP at
  runtime — they're built as spline UDCs by
  `build_estol_geometry.py`. The UDP only appears in legacy code paths.)
- **Body-level `_name` does NOT propagate to faces.** Face tagging
  must use `select face / attribute capsGroup $<name>` per face.
- **Bodies are disjoint solids on purpose.** We never boolean-union
  the main wing, vane, aft flap, and H-tail; the 3-element high-lift
  system has *physical* slot gaps and Flow360 wants each surface as
  its own boundary anyway.
- **Fowler ordering.** Apply `rotatez` + `translate` for the
  Fowler kinematics in the **normalized** chord frame, BEFORE
  `scale wing_chord`. Doing it after scaling double-scales the
  motion.
